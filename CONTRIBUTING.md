# Contributing

Contributions that improve clarity, correctness, or reproducibility of the reference implementation are welcome.

## Setup

```bash
git clone https://github.com/roy-saurabh/rcea-passport-engine.git
cd rcea-passport-engine
pip install -e ".[dev,notebooks]"
pytest tests/ -v
```

## Adding a new governance role

1. Add a new `RoleProfile` entry to the relevant `examples/<name>/role_profiles.json`.
2. Add a corresponding entry to `examples/<name>/rule_pack.json` defining the role's evidence policies.
3. Add test cases in `tests/test_scoring.py` and `tests/test_passport_reproducibility.py` for the new role.
4. Run `pytest tests/ -v` and confirm all tests pass.

## Adding a new rule

1. Implement the rule logic in `rcea/rules.py`, following the existing `RuleResult` return convention.
2. Register the rule in the relevant `rule_pack.json` under the appropriate role(s).
3. Add a targeted test in `tests/test_scoring.py`.
4. Update `CHANGELOG.md`.

## Adding a new requirement profile

1. Add the profile definition to the relevant `role_profiles.json` under `requirement_profile`.
2. Ensure the scoring functions in `rcea/scoring.py` handle any new dimension weights.
3. Add tests covering the new profile's score expectations.

## Adding a new synthetic example

1. Create a new directory under `examples/<example_name>/` with the following files:
   - `evidence_finding.json`
   - `context_pack.json`
   - `role_profiles.json`
   - `rule_pack.json`
   - `outputs/` (initially empty; generated by CLI scripts)
2. Ensure the example is purely synthetic — no real personal data, system identifiers, or proprietary content.
3. Add the example to the table in `README.md`.
4. Add integration tests in `tests/test_passport_reproducibility.py`.
5. Update `scripts/reproduce_paper_tables.py` if the example should appear in paper artefacts.

## Running tests

```bash
pytest tests/ -v                        # all tests
pytest tests/test_scoring.py -v        # scoring tests only
pytest tests/ -v --cov=rcea            # with coverage
```

## Pull requests

- Keep changes focused; one concern per PR.
- All tests must pass before review.
- Update `CHANGELOG.md` under a new `[Unreleased]` section.
